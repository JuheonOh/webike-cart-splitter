# 2026-05-06 Webike 주문그룹 자동화 설계안

## 문서 목적

이 문서는 `japan-webike.kr` 기준으로 다음 작업을 자동화하기 위한 설계안을 정리한다.

- 사용자가 입력한 부품번호와 수량을 기준으로 상품을 검색한다.
- 필요 시 로그인 후 장바구니에 자동으로 담는다.
- 동일한 조회 결과를 기준으로 상품가격만 계산한다.
- 관세청 기준 환율을 조회해 150 USD 미만 주문 그룹을 계산한다.
- 결과를 Excel 파일로 출력한다.

실제 주문 분할과 결제는 자동화하지 않는다. 사용자가 결과 Excel을 보고 수동으로 진행한다.

## 목표

1. 사용자가 사이트에서 부품을 직접 검색하고 장바구니에 담는 반복 작업을 줄인다.
2. 입력 파일의 `부품번호`, `수량`만으로 가격 조회와 그룹 계획까지 한 번에 끝낸다.
3. 그룹 계산은 배송비 제외, 상품가격 기준으로만 수행한다.
4. 결과는 재검토 가능한 Excel 파일로 남긴다.

## 범위

### 포함

- `.env`에서 계정정보 읽기
- 품번 검색
- 정확 일치 상품 선택
- 장바구니 자동 담기
- 상품가격 수집
- 관세청 기준 환율 조회
- 150 USD 미만 그룹 계산
- Excel 결과 출력

### 제외

- 배송비 계산
- 실제 주문 버튼 클릭
- 결제 자동화
- 합산과세 회피 보장
- 다중 후보 상품의 자동 추측 선택

## 기본 전제

- 실제 주문은 사용자가 수동으로 진행한다.
- 그룹 계산의 목적은 "가격 기준 주문 계획"이다.
- 세금과 통관 결과를 보장하는 도구가 아니다.
- 입력 품번은 가능한 한 정확한 OEM 부품번호라고 가정한다.

## 사용자 시나리오

1. 사용자가 `input.xlsx` 또는 `input.csv`를 준비한다.
2. 스크립트를 실행한다.
3. 스크립트가 `.env`에서 Webike 계정정보를 읽는다.
4. Webike에 로그인한다.
5. 각 품번을 검색하고 정확 일치 상품을 찾는다.
6. 매칭 성공 품목은 수량만큼 장바구니에 담는다.
7. 동일한 조회 결과에서 단가와 소계를 수집한다.
8. 관세청 기준 환율을 조회한다.
9. 150 USD를 JPY 한도로 환산한다.
10. 모든 품목을 한도 이하 그룹들로 분배한다.
11. 결과를 `result_YYYYMMDD_HHMM.xlsx`로 저장한다.

## 입력 포맷

### 입력 파일

- 파일 형식: `.xlsx`, `.csv`
- 필수 컬럼:
  - `part_number`
  - `quantity`
- 선택 컬럼:
  - `memo`
  - `brand`

### 전처리 규칙

- 품번 앞뒤 공백 제거
- 대소문자 정규화
- 하이픈/공백이 섞인 경우 검색용 표준 포맷으로 변환
- 동일 품번 중복 행은 합산
- 수량이 1 미만 또는 숫자가 아니면 예외 처리

## 출력 포맷

출력 파일은 하나의 `.xlsx`로 생성한다.

### `summary` 시트

- 실행 시각
- 환율 소스 URL
- 환율 조회 시각
- USD 환율
- JPY 환율
- 150 USD 환산 JPY 한도
- 총 입력 행 수
- 총 매칭 성공 수
- 총 매칭 실패 수
- 총 상품금액 JPY
- 추천 그룹 수

### `matched_parts` 시트

- 입력 품번
- 입력 수량
- 매칭 상품명
- 매칭 상품 URL
- 조회 단가 JPY
- 소계 JPY
- 장바구니 담기 성공 여부
- 비고

### `groups` 시트

- 그룹 번호
- 품번
- 상품명
- 수량
- 단가 JPY
- 소계 JPY
- 그룹 합계 JPY
- 그룹 합계 USD 환산

### `exceptions` 시트

- 입력 품번
- 입력 수량
- 상태 코드
- 실패 사유
- 후보 수
- 관련 URL 또는 검색 키워드

## 크롤링 설계

### 기술 선택

- 기본 기술: `Python + Playwright`

선정 이유:

- 로그인 세션 제어 필요
- 검색 결과/상품 상세 렌더링 대응
- 장바구니 담기 동작 재현 필요

### 세션 전략

- 실행 시작 시 1회 로그인
- 로그인 후 세션 상태 재사용
- 같은 실행 내에서는 재로그인하지 않음

### 성능 전략

- 동일 품번 재검색 금지
- 품번 결과 캐시 저장
- 하나의 브라우저 세션을 계속 사용
- 병렬화는 제한적으로만 허용
- 필요 시 느린 페이지는 재시도

## 상품 매칭 규칙

### 자동 선택 허용 조건

다음 조건을 만족할 때만 자동 선택한다.

1. 검색 결과의 품번 표기가 입력 품번과 정확히 일치한다.
2. 상품 상세 페이지의 품번 정보가 입력 품번과 정확히 일치한다.
3. 정확 일치 후보가 1개뿐이다.

### 자동 선택 금지 조건

- 동일 품번처럼 보이지만 표기가 다름
- 동일 품번 후보가 2개 이상
- 옵션 선택이 필요한 상품
- 품절 또는 판매 불가 상태

이 경우 `exceptions` 시트에 기록하고 장바구니에 담지 않는다.

## 장바구니 자동 담기 설계

### 처리 흐름

1. 매칭된 상품 상세로 이동
2. 수량 입력
3. 장바구니 추가 버튼 실행
4. 성공 여부 확인

### 성공 판정

- 성공 메시지 노출
- 장바구니 수량 증가
- 또는 장바구니 페이지 반영 여부

### 실패 판정

- 버튼 동작 없음
- 오류 메시지 발생
- 수량 제한 또는 품절
- 로그인 세션 만료

실패 시 즉시 예외 시트에 기록한다.

## 환율 조회 설계

### 목표

- 실행 시점 기준 환율 자동 조회
- JPY 한도를 수동 입력 없이 계산

### 처리 방식

1. 고정된 공식 환율 소스 URL 접근
2. USD/JPY 값을 파싱
3. 환율 조회 시각과 소스 URL을 `summary` 시트에 기록

### 실패 처리

- 환율 조회 실패 시 기본 동작은 실행 중단
- 필요 시 향후 `수동 환율 override` 옵션 추가 가능

### 계산식

```text
limit_jpy = 150 * usd_krw / jpy_krw
```

## 그룹 계산 설계

### 그룹 기준

- 배송비 제외
- 상품가격만 기준
- 각 그룹 합계는 `limit_jpy` 이하

### 수량 처리

- 동일 품번의 수량 분할 기본값: 허용
- 예: 수량 4개면 1개씩 다른 그룹에 분산 가능

### 알고리즘

- 2그룹 문제:
  - 가능한 경우 동적 계획법 우선
- 3그룹 이상:
  - First-Fit Decreasing 계열 휴리스틱

### 목표

1. 모든 품목을 누락 없이 배치
2. 그룹 수 최소화
3. 각 그룹 한도 초과 금지
4. 그룹 금액 균형이 지나치게 깨지지 않도록 정렬

## 예외 처리

### 입력 단계

- 품번 누락
- 수량 오류
- 중복 품번

### 검색 단계

- 검색 결과 없음
- 다중 후보
- 품절
- 가격 미노출

### 장바구니 단계

- 로그인 실패
- 버튼 동작 실패
- 수량 제한

### 환율 단계

- 페이지 접근 실패
- 환율 파싱 실패

모든 예외는 `exceptions` 시트에 남긴다.

### `.env` 항목

- `WEBIKE_EMAIL`

### 원칙

- 계정정보를 로그에 출력하지 않는다.

## 실행 모드 제안

### `plan-only`

- 가격 조회
- 환율 조회
- 그룹 Excel 생성

### `fill-cart-only`

- 로그인
- 품번 검색
- 장바구니 담기
- 결과 리포트 생성

### `all`

- 장바구니 담기
- 가격 조회
- 환율 조회
- 그룹 Excel 생성

## 구현 우선순위

1. `plan-only`
2. `fill-cart-only`
3. `all`

이 순서가 가장 보수적이다. 품번 매칭과 가격 조회가 먼저 안정돼야 장바구니 자동 담기 리스크도 줄어든다.

## 리스크와 한계

- 상품 상세 구조가 바뀌면 크롤러 수정 필요
- 동일 품번의 다중 후보는 자동 처리하지 않음
- 배송비를 계산하지 않으므로 실제 총구매비용 최적화 도구는 아님
- 결과는 가격 기준 계획 자료일 뿐, 통관 결과를 보장하지 않음
