# Webike 배송비 실측 자동화

## 배경

- 분할 주문이 실제로 더 싼지 판단하려면 Webike 장바구니에 단일 주문과 분할 주문 그룹을 각각 담아 배송비를 확인해야 한다.
- 배송비는 주소 입력 없이 장바구니 상품 구성만으로 자동 책정된다.
- 사람이 장바구니를 반복 구성하지 않도록 Node/Playwright CLI로 장바구니 배송비를 실측한다.

## 승인 설계

- Playwright 브라우저 1개를 실행하고 주문 시나리오마다 새 browser context를 만든다.
- 단일 주문을 먼저 새 context에서 담아 실제 상품가와 배송비를 읽는다.
- 단일 주문에서 읽은 상품가로 추천 분할 그룹을 계산한다.
- 분할 그룹마다 새 context를 만들어 장바구니를 구성하고 배송비를 읽는다.
- 장바구니 비우기 방식은 실패 시 상품이 섞일 수 있으므로 기본 방식에서 제외한다.

## 상품 상세 분석 후 추가 승인 설계

- 상품 상세 페이지는 `priceYen`, `productWeight`, `productVolume`, `currentCountryIso2`, `shopCode`, `API_SHIPPING_URL` 값을 페이지 안에 노출한다.
- 배송비 API는 `wp`, `vl`, `to`, `sc`, `amount` 파라미터로 배송 후보와 비용을 반환한다.
- 상품 URL이 없으면 Webike 검색 API `api-search-es.html`에 `p.k={part_number}`를 넘겨 상세 URL을 찾는다.
- 장바구니 반복 구성보다 상품 상세 파싱 + 배송비 API 직접 호출을 기본 자동화 경로로 둔다.
- Playwright 장바구니 측정은 실제 화면 검증 또는 API 경로 실패 시 예비 경로로 둔다.

## DevTools 장바구니 일괄 담기 추가 승인 설계

- 사이트 응답이 느릴 때 Playwright로 상품을 하나씩 담는 대신, CLI가 상품 상세에서 `products_id`를 확정해 브라우저 Console용 JS를 생성한다.
- 생성된 JS는 Webike 페이지의 현재 브라우저 세션에서 `/api_shopping_cart.html?action=add_product&ajax_action=1`에 `products_id`, `cart_quantity`를 POST한다.
- 각 상품의 성공/실패를 Console에 출력하고, 실패가 있으면 실패 목록만 남긴 뒤 이동하지 않는다.
- 모든 상품이 성공하면 `/shopping_cart.html`로 이동해 사용자가 배송비와 상품 구성을 직접 확인한다.
- CLI는 스크립트 파일 생성까지만 수행하며, 주문/결제/로그인 자동화는 하지 않는다.

## 계산기 화면 접근성 개선 승인 설계

- 일반 사용자가 터미널 없이 `cart_group_calculator.html`에서 현재 상품 기준 장바구니 담기 스크립트를 생성하고 복사할 수 있게 한다.
- 계산기 화면에서 만드는 스크립트는 Webike 페이지에서 실행될 때 부품번호 검색, 상품 상세 확인, `products_id` 추출, 장바구니 담기를 순서대로 수행한다.
- 수량/단가를 수정한 뒤에도 현재 결과표 값을 읽어 스크립트를 생성한다.
- 복사 버튼과 진행 순서를 제공하되 주문, 결제, 로그인 자동화는 제외한다.

## 구현 범위

- `assets/js/cost-comparison-core.js`
  - 고정 배송비 기반 비교
  - 실측 배송비 기반 비교
  - 관세/부가세 예상 계산
- `assets/js/cart-group-calculator.js`
  - 결과 화면에서 Webike 장바구니 담기 스크립트 생성/복사
  - 결과표 수정값 기준 스크립트 생성
- `scripts/webike-quote.js`
  - `quote-api` 모드: 상품 상세 페이지 파싱, 배송비 API 직접 호출
  - `cart-script` 모드: Webike DevTools Console에 붙여넣을 장바구니 일괄 담기 JS 생성
  - `plan-only` 모드: 입력 가격과 예상 배송비로 비교
  - `cart` 모드: Webike 검색, 정확 후보 확인, 장바구니 담기, 배송비 실측
  - 단일 주문 견적 후 추천 분할 그룹별 재견적
  - 상품 담기 실패, 빈 장바구니, 배송비 미검출 시 실패 처리
- `tests/cost_comparison.test.js`
  - 고정 배송비 비교
  - 실측 배송비 비교
  - CLI 입력 병합
  - 상품 상세 fixture 파싱
  - 배송비 API fixture 정규화
  - 배송비 API 기반 견적 흐름
  - DevTools 장바구니 일괄 담기 스크립트 생성
  - 장바구니 측정 실패 검증
- `tests/cart_group_calculator.test.js`
  - 계산기 화면의 Webike 장바구니 스크립트 생성 UI와 HTML-like 데이터 escape 검증

## 운영 메모

```bash
npm install
npm run webike:install
npm run webike:quote -- --mode quote-api --input parts.csv
npm run webike:quote -- --mode cart-script --input parts.csv --output /tmp/webike_add_cart.js
npm run webike:quote -- --mode cart --input parts.csv --headed
```

입력 파일 컬럼:

```text
part_number,product_url,quantity,name,unit_jpy
```

- `quote-api` 모드는 `product_url`, `quantity`를 우선 사용한다.
- `part_number`만 있으면 검색 API 결과에서 상품 상세 URL이 1개로 확정될 때만 진행한다.
- 배송 서비스는 기본 최저가이며, 필요하면 `--shipping-service STD`처럼 고정한다.
- 실행 중 검색, 상세 조회, 배송비 조회 진행 상황을 터미널에 출력한다. 자동 실행에서 숨기려면 `--quiet`를 사용한다.
- `cart-script` 모드는 생성된 JS 파일을 Webike 페이지의 DevTools Console에 붙여넣어 현재 브라우저 세션 장바구니에 담는다.
- 계산기 화면의 `Webike 장바구니 담기`는 터미널 없이 같은 목적의 스크립트를 생성한다.
- `cart` 모드에서는 `unit_jpy`가 없어도 된다.
- 실제 Webike DOM 검증 전까지 selector는 보수적인 후보 기반이다.
- Webike DOM이 바뀌면 `--headed`로 확인 후 selector 보정이 필요하다.
